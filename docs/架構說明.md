# 系統架構說明

## 總覽

本原型採「資料層 → 特徵／模型層 → 決策／解釋層 → 應用層控制平面 → 呈現層」架構，便於備審口試時對照說明。

## 資料流（口試可用口述稿）

1. 啟動 App → 合成帳號登入（失敗亦寫稽核）→ 依門市範圍載入 CSV
2. 首次載入訓練 MA 與 RandomForest，結果寫入 joblib 快取
3. 使用者選**可見**門市／品類與 horizon → 遞迴多步預測
4. 以特徵重要性與類似歷史日說明「為什麼」
5. 規則引擎依預測量與庫存產出補貨／人力文字建議，並標示存取風險
6. 提出／核准補貨或調整庫存時：權限 → 範圍 → 信任條件 → 通過才寫入；結果追加進稽核
7. 評估頁對照 baseline 與進階模型之 MAE／MAPE
8. 管理者可篩選、匯出稽核（失敗授權與敏感成功）

## 模組對應

| 模組 | 職責 |
|------|------|
| `generate_data.py` | 可重現合成資料 |
| `src/data_loader.py` | 載入與維度清單 |
| `src/features.py` | 特徵工程 |
| `src/models.py` | 訓練、評估、預測、快取 |
| `src/explain.py` | 重要性與歷史類比 |
| `src/recommend.py` | 補貨／人力建議 |
| `src/access/` | 細粒度政策、門市範圍、稽核、種子帳號 |
| `src/ui_security.py` | 登入、風險提示、作業／稽核／設定頁 |
| `app.py` | Streamlit 介面 |

## 設計取捨

- **選 RandomForest**：依賴輕、訓練快、原生特徵重要性，適合備審現場 Demo
- **規則型建議**：刻意與預測模型分離，凸顯「DSS = 模型 + 管理邏輯」
- **應用層授權／稽核**：把補貨與庫存從「畫面上看得到」變成「有權限、有範圍、有紀錄才做得到」；不宣稱等同生產零信任
- **合成資料**：保證一鍵重現與無授權爭議；研究階段可置換真實資料驗證外推能力
