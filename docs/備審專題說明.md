# 備審專題說明

字數約 550 字｜繁體中文

---

我做的 Retail Ops DSS 是一套可 Demo 的零售營運資訊系統原型。資料是程式產生的合成日銷量（四門市、四品類、約兩年），固定亂數種子可重現。系統一開始只做銷量預測（七日移動平均對照隨機森林）和補貨、人力的文字建議。做到一半我發現：預測再準，只要誰都能改庫存、核准補貨，或做過的事查不到，這個系統就沒辦法真的交給別人用。所以後半段的重點放在權限和操作紀錄。

角色分成檢視、門市營運、管理者三種。每個動作先查這個角色能不能做；權限表（`src/access/policy.py`）裡沒有列的動作一律拒絕。門市營運人員只能看、只能改被指派的門市，跨店操作會被擋下並留下紀錄。數量很大的補貨核准、變更系統設定等，要在約五分鐘內再驗證一次身分才放行。成功和被拒絕的操作都寫進 SQLite，並以 BEFORE UPDATE／DELETE trigger 做成只能新增、不能修改或刪除；管理者可以篩選和匯出。

我寫了 24 個測試（以存取控制為主），涵蓋預設拒絕、角色限制、資料範圍、再驗證與操作紀錄。每次更新程式都會在 GitHub Actions 自動重跑；2026-10-06 驗證通過。想自己確認的話，照 README 在本機執行後：用 viewer.s02 試著改庫存會被拒絕；用 operator.s01 替別家門市補貨會被拒絕並留下紀錄；再用 admin 打開稽核頁，就看得到剛才成功和被拒絕的事件。

我學到的是：權限和紀錄最好一開始就設計進去，而且要寫成能自動重跑的測試，改程式時才知道有沒有不小心打開缺口。這份作品的權限表、測試案例與事件紀錄，會作為我碩士班往資訊系統與存取控管方向繼續做的起點。
